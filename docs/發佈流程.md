# 發佈流程（第一次發 Release 就照這份做）

這份文件寫給**第一次在 GitHub 發佈 Release** 的人。從打包到發佈，照順序做完大約 20 分鐘。

> **重點觀念**：GitHub 的「Release」就是一個附上檔案的正式版本標記。使用者到 Releases 頁面點一下就能下載 ZIP，不用碰程式碼。
> 目前 README 和新手教學都叫使用者「到 Releases 下載」，所以**這一步沒做，公開倉庫後使用者會下載不到東西**。

---

## 階段一：在 Windows 電腦上打包（產出 ZIP）

> 這個階段**一定要在 Windows 上做**，因為程式是 Windows 桌面應用程式。

### 步驟 1：確認開發環境

打開 **PowerShell**（開始選單搜尋「PowerShell」），輸入：

```powershell
dotnet --version
```

- **有顯示版本號**（需要 **10.x** 或更新）→ 繼續下一步。
- **顯示「找不到命令」或版本太舊** → 到 <https://dotnet.microsoft.com/download> 下載安裝 **.NET 10 SDK**（要選 SDK，不是 Runtime），裝完**重開 PowerShell** 再試一次。

### 步驟 2：把專案抓到電腦上

如果還沒有原始碼：

```powershell
cd C:\
git clone https://github.com/zellhuang0503/Codex-Model-Switcher.git
cd Codex-Model-Switcher
```

如果已經有了，記得先更新到最新：

```powershell
cd C:\Codex-Model-Switcher
git checkout main
git pull
```

### 步驟 3：先跑測試（確認程式沒壞）

```powershell
dotnet test tests/CodexModelSwitcher.Tests.csproj
```

看到 **`Passed!`** 且失敗數為 0 才繼續。
如果有測試失敗，**先不要發佈**，把失敗訊息貼出來處理。

### 步驟 4：執行打包腳本

```powershell
.\build-portable.ps1
```

> **如果出現「因為這個系統上已停用指令碼執行」的紅字**，代表 PowerShell 的執行原則擋住了。改用這一行（只對這次執行放行，不會改變系統設定）：
>
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\build-portable.ps1
> ```

腳本會自動做完這些事：編譯 → 檢查發佈內容白名單 → 掃描是否夾帶金鑰（連 .exe 的二進位內容都掃）→ 壓縮 → 驗證 ZIP 內容。

### 步驟 5：記下腳本印出的資訊

成功時最後會印出類似這樣的內容：

```
WINDOWS_PORTABLE_PREVIEW_OK
版本：0.9.0
ZIP：C:\Codex-Model-Switcher\release\Codex-Model-Switcher-Windows-x64-v0.9.0.zip
大小：xxxxxxx bytes
SHA256：A1B2C3D4E5F6.....（一長串英數字）
```

**請把「版本」「ZIP 路徑」「SHA256」三個值複製到記事本**，等一下發佈時要用。

> **SHA256 是什麼？** 這是檔案的「指紋」。使用者下載後可以自己算一次，比對得上就代表檔案沒有被掉包或損毀。因為這支程式沒有購買程式碼簽章，公布 SHA256 是讓使用者驗證來源的重要方式，**一定要放進 Release 說明裡**。

### 步驟 6（強烈建議）：自己先測一次

在**另一個資料夾**解壓縮剛產生的 ZIP，雙擊執行看看能不能正常開啟主視窗。
第一次發佈就發出一個打不開的檔案會很尷尬，花兩分鐘測一下很值得。

## 階段二：在 GitHub 網頁上發佈 Release

### 步驟 7：進入 Release 建立頁面

打開瀏覽器，到：

**<https://github.com/zellhuang0503/Codex-Model-Switcher/releases/new>**

（也可以從倉庫首頁右側找到 **Releases** → 點 **Draft a new release**。）

### 步驟 8：建立版本標籤（Tag）

1. 點畫面左上角的 **`Choose a tag`** 下拉框。
2. 在輸入框直接打上 **`v0.9.0`**（要跟 `build-portable.ps1` 印出的版本一致，前面加一個小寫 `v`）。
3. 下方會出現 **`+ Create new tag: v0.9.0 on publish`**，**點它**。
4. 右邊的 **Target** 保持 **`main`** 不要改。

> **Tag 是什麼？** 就是在程式碼歷史上插一根旗子，標記「這個版本是從這個時間點的程式碼做出來的」。以後要回頭找某一版的原始碼就靠它。

### 步驟 9：填標題

**Release title** 欄位填：

```
v0.9.0 — Windows 可攜測試版
```

### 步驟 10：填說明內容

在大的說明框裡貼上以下內容，**記得把 SHA256 換成你剛剛複製的那一串**：

````markdown
Windows 可攜版第一次公開測試release。解壓縮後雙擊即可使用，不需安裝 .NET，不需系統管理員權限。

## 安裝方式

1. 下載下方的 `Codex-Model-Switcher-Windows-x64-v0.9.0.zip`
2. 解壓縮到一個**固定不會搬動的資料夾**，例如 `C:\Tools\Codex-Model-Switcher`
3. 雙擊 `CodexModelSwitcher.exe`

**第一次使用請先看 [新手完整教學](https://github.com/zellhuang0503/Codex-Model-Switcher/blob/main/docs/新手教學.md)。**

## 本版支援

- OpenAI（沿用 Codex 原生登入，不需金鑰）
- DeepSeek V4 Flash / V4 Pro
- MiniMax M3 / M2.7
- 自訂 OpenAI Responses API 相容供應商（需通過文字與工具呼叫雙驗證）

## 使用前請注意

- **需自備 API Key**，費用由使用者自行負擔。本工具不含任何金鑰。
- 金鑰只存於你電腦的 Windows 認證管理員，不寫入設定檔、不隨 ZIP 散布。程式沒有遙測。
- **本程式尚未購買程式碼簽章**，首次執行時 Windows SmartScreen 可能顯示未知發行者警告，這是未簽章程式的預期行為。請比對下方 SHA256 後再決定是否執行。
- 切換後 Codex 模型選單顯示「自訂」是正常現象。
- 切換後 Codex 送出的提示與專案片段會傳給你選擇的供應商，請勿處理未經授權的個資或機密資料。

## 檔案校驗

```
SHA256: 在這裡貼上 build-portable.ps1 印出的那一串
```

Windows 上驗證方式（在下載資料夾開啟 PowerShell）：

```powershell
Get-FileHash .\Codex-Model-Switcher-Windows-x64-v0.9.0.zip -Algorithm SHA256
```

算出來的值要跟上面完全一致。

## 已知限制

- 僅支援 Windows 10 / 11（64 位元），尚未支援 macOS 與 Linux
- 沒有自動更新，新版本請自行回本頁下載
- 未包含 Gemini、Kimi、Z.AI GLM

---

本工具為個人開發的非官方工具，與 OpenAI、DeepSeek、MiniMax 均無隸屬關係。依 MIT License 釋出，按「現狀」提供，不附任何擔保。
````

### 步驟 11：上傳 ZIP 檔案

在說明框下方會看到一塊虛線區域，寫著 **`Attach binaries by dropping them here or selecting them.`**

1. 點那塊區域（或直接把檔案拖進去）。
2. 選擇步驟 5 記下的那個 ZIP：`release\Codex-Model-Switcher-Windows-x64-v0.9.0.zip`
3. **等待上傳完成**——檔名旁邊的進度條要跑完，不要提早按發佈。

> ⚠️ **只上傳 ZIP，不要上傳其他東西。** 尤其不要上傳 `release\work\` 底下的中間產物。

### 步驟 12：勾選「預先發行版本」

在按鈕上方找到勾選框：

- ☑️ **Set as a pre-release** ← **請勾這個**

因為目前是 0.9.0 測試版。勾了之後 GitHub 會標上黃色的 `Pre-release` 標籤，使用者一看就知道還在測試階段，期待值會比較合理。

- ☐ Set as the latest release ← 測試版**先不要勾**

### 步驟 13：發佈

點綠色的 **`Publish release`** 按鈕。

完成！現在到 <https://github.com/zellhuang0503/Codex-Model-Switcher/releases> 應該就看得到了。

## 階段三：發佈後確認

**用「別人的角度」自己驗收一次：**

1. 開一個**無痕視窗**，打開 Releases 頁面（模擬沒登入的訪客看到的畫面）。
2. 確認 ZIP 檔案在 **Assets** 區塊裡可以點擊下載。
3. **實際點下載**，確認檔案抓得下來。
4. 執行 `Get-FileHash` 比對 SHA256，確認跟說明裡寫的一致。
5. 確認 README 的 [Releases](../../releases) 連結點過去有東西。

這五項都過了，**才可以把倉庫從 Private 改成 Public**。

---

## 之後要發新版本時

1. 修改 `CodexModelSwitcher.csproj` 裡的 `<Version>0.9.0</Version>` 改成新版號（例如 `0.9.1`）。
2. commit 並 push。
3. 重複階段一與階段二，tag 改用新版號（例如 `v0.9.1`）。

> `build-portable.ps1` 以 `.csproj` 的版本號為唯一事實來源，ZIP 檔名會自動跟著變，不用手動改檔名。
> 腳本也會自動清掉 `release\` 裡的舊版 ZIP，避免不小心傳錯版本。

## 卡住時的對照表

| 狀況 | 原因 | 解法 |
| --- | --- | --- |
| `dotnet` 不是內部或外部命令 | 沒裝 .NET SDK | 安裝 .NET 10 SDK 後重開 PowerShell |
| 因為這個系統上已停用指令碼執行 | PowerShell 執行原則 | 改用 `powershell -ExecutionPolicy Bypass -File .\build-portable.ps1` |
| 專案檔缺少 Version 設定 | `.csproj` 的 `<Version>` 被刪掉了 | 補回 `<Version>0.9.0</Version>` |
| 發佈內容不符合白名單 | `release` 資料夾有殘留檔案 | 刪掉整個 `release` 資料夾後重跑 |
| 發佈執行檔疑似包含敏感內容 | 掃到疑似金鑰字串 | **不要強行發佈**，先確認是否誤把金鑰寫進程式碼 |
| Tag 已經存在 | 這個版號發佈過了 | 改用新版號，或先刪掉舊 tag |
| 上傳 ZIP 一直失敗 | 網路或檔案過大 | 重新整理頁面重試；草稿會被保留 |
