# Codex Model Switcher：Windows 可攜版 MVP 設計

日期：2026-08-14
狀態：專案負責人已核准產品方向，尚未開始實作

## 1. 產品目標

建立一個可下載分享的 Windows 可攜版工具。使用者解壓縮 ZIP 並雙擊執行後，可以在單一圖形介面查看與切換 Codex App 的模型供應商與模型，不必建立一模型一捷徑，也不必手動修改 Codex 設定。

MVP 的核心成功條件：

- 非工程使用者能在五分鐘內完成首次設定。
- 桌面最多只需要一個程式圖示。
- 模型切換不破壞既有 Codex 插件、MCP Server、權限及專案信任設定。
- API Key 不出現在 Git、一般設定檔、畫面、記錄或發佈 ZIP。
- 切換失敗時，原本可用的 Codex 設定仍可復原。

## 2. 已選技術方案

採用 C# Windows 原生桌面應用程式，發佈為自包含可攜版 ZIP。

選擇理由：

- 可提供單一可雙擊執行檔。
- 不受 PowerShell 執行政策影響。
- 不需要 Electron 等大型瀏覽器執行環境。
- 適合使用 Windows 認證管理員、檔案鎖定、原子寫入與原生對話框。
- 未來可以沿用主要程式碼製作正式安裝版。

MVP 不製作背景常駐服務，也不要求管理員權限。

## 3. 發佈內容

使用者下載的 ZIP 預定包含：

```text
Codex-Model-Switcher/
├─ CodexModelSwitcher.exe
├─ providers.json
└─ 使用說明.html
```

- `CodexModelSwitcher.exe`：圖形介面、設定切換、備份、驗證與安全取用金鑰。
- `providers.json`：不含金鑰的供應商與模型目錄。
- `使用說明.html`：首次使用、金鑰申請、切換、復原與常見錯誤說明。

## 4. MVP 供應商

### 4.1 OpenAI

- 使用 Codex 原本的 ChatGPT／OpenAI 登入方式。
- 切回 OpenAI 後，使用者仍可使用 Codex 原生模型選單選擇其他 OpenAI 模型。
- 切換器不保存 OpenAI 帳號密碼或工作階段憑證。

### 4.2 DeepSeek

- DeepSeek V4 Flash
- DeepSeek V4 Pro
- 使用 DeepSeek 官方 Responses API 與模型目錄資訊。
- API Key 存入 Windows 認證管理員。

### 4.3 MiniMax

- MiniMax M3
- 使用 MiniMax 國際版官方 Responses API。
- API Key 存入 Windows 認證管理員。

### 4.4 自訂供應商

只接受使用者明確標示為 OpenAI Responses API 相容的供應商，欄位包含：

- 顯示名稱
- Base URL
- 模型 ID
- API Key
- 上下文長度
- 是否支援圖片
- 可用推理等級

加入前先測試最小文字回應與工具呼叫；任一測試失敗，不得標示為已可用。

## 5. 第二版候選

Gemini、Kimi 與 Z.AI 國際版 GLM 不納入 MVP。其官方國際 API 目前主要使用 Chat Completions 或 Anthropic 格式，不能假設與 Codex 所需的 Responses API 完整相容。

第二版只考慮：

- 官方新增 Responses API；或
- 經專案負責人核准並完成資料流、費用、工具呼叫及隱私驗證的統一路由平台。

MVP 不自行開發協定轉接服務。

## 6. 應用程式元件

### 6.1 主視窗

顯示：

- 目前供應商與模型
- 供應商選單
- 模型選單
- 金鑰狀態：未設定／已保存／驗證失敗
- `設定 API Key`
- `測試連線`
- `切換並開啟 Codex`
- `恢復原始設定`

不得在任何畫面顯示已保存金鑰的完整值。

### 6.2 Provider Catalog

讀取 `providers.json`，提供內建供應商與模型資料。目錄不保存金鑰。

若目錄格式錯誤，程式使用內建的最低安全目錄啟動，並禁止使用損壞的自訂項目。

### 6.3 Credential Vault

使用 Windows 認證管理員依供應商保存金鑰。

Codex 需要驗證時，透過 `CodexModelSwitcher.exe token <provider-id>` 命令取得短暫權杖輸出。這個模式對應 Codex 自訂供應商的命令式驗證功能，避免把金鑰寫進 `config.toml` 或使用者環境變數。

命令模式：

- 只將權杖寫到標準輸出。
- 不寫入記錄檔。
- 不接受不在目錄中的供應商 ID。
- 找不到金鑰時回傳非零結束碼，不回傳空白成功。

### 6.4 Codex Config Engine

責任：

1. 找出使用者的 Codex 設定位置。
2. 取得設定檔鎖，避免同時寫入。
3. 解析既有 TOML。
4. 只修改模型、供應商、目錄與驗證相關欄位。
5. 產生暫存檔並驗證。
6. 建立帶日期時間的備份。
7. 以單次取代方式更新正式檔案。
8. 寫入失敗時保留原設定。

不得刪除或重排與模型切換無關的設定。

### 6.5 Active Model Catalog

切換器依目前供應商產生 Codex 使用的模型目錄，只包含該供應商可用模型，避免把 DeepSeek 模型送到 MiniMax 網址或反向誤用。

產生後必須通過 JSON 格式與必要欄位驗證。

### 6.6 Backup Manager

備份放在 Codex 使用者資料夾下的切換器專屬子資料夾，不放進應用程式 ZIP 或使用者專案。

保留：

- 首次使用前的原始設定
- 最近五次成功切換前的設定

刪除舊備份前必須確認至少仍保留首次原始備份與一份最近可用備份。

## 7. 切換流程

1. 使用者開啟切換器。
2. 程式讀取並顯示目前設定。
3. 使用者選擇供應商與模型。
4. 若需要金鑰但尚未設定，先開啟金鑰設定視窗。
5. 使用者可執行最小連線測試。
6. 程式確認 Codex 是否正在執行；若正在執行，要求使用者保存工作並自行關閉，不強制終止。
7. 取得設定鎖並建立備份。
8. 產生、解析並驗證暫存設定與模型目錄。
9. 驗證成功後更新正式設定。
10. 重新讀取正式設定，確認目標供應商與模型正確。
11. 開啟 Codex App。

## 8. 恢復流程

`恢復原始設定` 會：

1. 顯示即將恢復的備份日期。
2. 要求使用者確認 Codex 已關閉。
3. 驗證備份可解析。
4. 先備份目前設定。
5. 恢復首次使用前的原始設定。
6. 重新驗證並開啟 Codex。

恢復不刪除 Windows 認證管理員內的金鑰；刪除金鑰是另一個明確操作。

## 9. 錯誤處理

- 找不到 Codex：提供官方安裝與首次啟動指引，不自行安裝。
- 找不到設定檔：請使用者先啟動一次 Codex。
- 未設定金鑰：禁止切換到需要金鑰的供應商。
- 認證失敗：顯示供應商、HTTP 狀態與一般化原因，不顯示金鑰或完整請求。
- 餘額不足或限流：保留原設定並提示切換其他供應商。
- 模型不存在：禁止選取並提示更新目錄。
- TOML 或 JSON 無效：停止寫入並保留原設定。
- Codex 尚未關閉：停止切換，不強制結束程序。
- 寫入失敗：保留原檔；若已取代則從最近備份恢復。
- 未預期錯誤：產生不含金鑰、路徑中的使用者名稱及專案內容的診斷摘要。

## 10. 隱私與資料流

- 切換器本身不讀取或上傳 Codex 專案內容。
- 切換後，Codex 為完成任務而送出的提示與專案片段會傳給所選供應商。
- 介面必須在首次啟用第三方供應商前顯示一次資料流提醒。
- 不加入遙測、廣告、使用者追蹤或遠端日誌。
- 發佈 ZIP 不包含任何開發者或測試者金鑰。

## 11. MVP 測試

### 11.1 自動測試

- 供應商目錄解析。
- 金鑰不存在、保存、讀取與刪除。
- TOML 局部修改不影響無關欄位。
- 暫存寫入、驗證、取代與失敗回復。
- 模型目錄 JSON 驗證。
- 備份保留規則。
- 診斷內容遮蔽金鑰與使用者名稱。

### 11.2 手動驗收

- 在乾淨 Windows 使用者帳號解壓縮並啟動。
- 不需管理員權限。
- OpenAI 切換後 Codex 可正常開啟。
- DeepSeek Flash、DeepSeek Pro、MiniMax M3 各完成一次短文字及工具呼叫測試。
- 錯誤金鑰不會破壞原設定。
- 恢復原始設定後，原有插件、MCP Server、權限與專案信任設定仍存在。
- ZIP、Git 差異、設定檔及診斷摘要均不包含 API Key。

所有會產生 API 費用的實際測試，必須先由測試者自行輸入金鑰並明確執行 `測試連線`。

## 12. 里程碑

每個里程碑最多修改或新增三個檔案，完成後等待專案負責人驗收。

1. 專案規則、README 與設計文件。
2. 應用程式骨架與主視窗。
3. 供應商目錄與模型選擇。
4. Windows 認證管理員與命令式驗證。
5. Codex 設定解析、備份與原子切換。
6. 連線測試、錯誤處理與診斷遮蔽。
7. 可攜版發佈、使用說明與乾淨環境驗收。

## 13. MVP 完成定義

只有同時符合以下條件才可稱為 MVP 完成：

- Windows 可攜版 ZIP 可在乾淨環境雙擊啟動。
- OpenAI、DeepSeek V4 Flash、DeepSeek V4 Pro、MiniMax M3 均依官方 API 實測成功。
- 自訂 Responses API 供應商通過文字與工具呼叫驗證後可啟用。
- 設定切換失敗不會讓 Codex 無法回復。
- API Key 未出現在任何非認證儲存位置。
- 使用說明足以讓非工程使用者完成首次設定與復原。
- 專案負責人完成親自驗收並說「通過」。
